# 💈 BarberFlow — учебный Telegram-бот для портфолио

Демонстрационный бот **выдуманной** парикмахерской. Все мастера, услуги, даты и время — тестовые.
Никаких реальных данных и платных сервисов.

**Что показывает проект:**
- Telegram Bot API (long polling, `python-telegram-bot` v21)
- inline-кнопки и редактирование сообщений вместо спама новыми
- состояние пользователя (услуга → мастер → дата → время)
- SQLite + защита от двойного бронирования одного слота (транзакция `BEGIN IMMEDIATE`)

**Сценарий:** `/start` → главное меню → «Записаться» → услуга → мастер → дата → время → подтверждение → запись в БД → экран успеха. Раздел «Моя запись» показывает текущую запись и позволяет её отменить (слот снова становится свободным).

## Структура

```
barberflow/
  main.py              — точка входа: init DB + seed + polling
  config.py            — BOT_TOKEN и DB_PATH из .env
  requirements.txt     — зависимости
  .env.example         — шаблон конфига
  .env                 — локальный конфиг (не коммитить)
  database/
    db.py              — схема SQLite + все запросы (включая атомарное бронирование)
    seed.py            — тестовые услуги, мастера, слоты (часть занята)
  bot/
    handlers.py        — /start и роутер inline-кнопок (редактирование сообщений)
    keyboards.py       — все inline-клавиатуры
    texts.py           — тексты сообщений
    states.py          — in-memory состояние выбора пользователя
  docs/                — статическая веб-витрина (GitHub Pages, без сборки)
    index.html         — «Северный клинок»: услуги, мастера, запись, отзывы, контакты
    styles.css         — собственная дизайн-система (бумага + графит + латунь)
    app.js             — демо-запись: услуга → мастер → дата/время → контакты → готово
    404.html           — страница ошибки для Pages
  tests/
    test_db_tmp.py     — проверка SQLite-слоя на временной копии БД
```

## SQLite-структура

- `users(id, telegram_id UNIQUE, name)`
- `services(id, name, price)`
- `masters(id, name)`
- `slots(id, master_id FK, date TEXT YYYY-MM-DD, time TEXT HH:MM, is_available 1/0)`
- `bookings(id, user_id FK, service_id FK, master_id FK, slot_id UNIQUE FK, created_at, status)`

Тестовые данные (`database/seed.py`):
- Услуги: Мужская стрижка — 1200 ₽, Стрижка + борода — 1700 ₽, Оформление бороды — 700 ₽
- Мастера: Алексей, Максим, Кирилл
- Слоты: ближайшие 5 дней (начиная с завтра), время 10:00 / 11:30 / 13:00 / 14:30 / 16:00 / 17:30
- ~1/3 слотов заранее помечены занятыми (`❌`), чтобы проверить логику недоступного времени

## Запуск локально на Windows

1. Установите Python 3.10+ (с галочкой «Add to PATH»).
2. Создайте бота через [@BotFather](https://t.me/BotFather) в Telegram, скопируйте токен.
3. В PowerShell:

```powershell
cd barberflow
python -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env
# откройте .env в блокноте и вставьте токен вместо PASTE_YOUR_TOKEN_HERE
python main.py
```

4. Откройте вашего бота в Telegram → `/start`.

Если PowerShell запрещает активацию скриптов, выполните один раз:
`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`, либо запускайте без активации:
`.\venv\Scripts\python.exe main.py`.

## Как проверить демо

1. `/start` → «Записаться» → выберите услугу, мастера, дату.
2. На шаге времени видны `✅` (свободно) и `❌` (занято). Нажатие на `❌` показывает алерт, выбрать его нельзя.
3. Подтвердите → запись создаётся, слот становится `is_available=0`.
4. «Моя запись» показывает детали. «Отменить запись» освобождает слот.
5. Попытка занять тот же слот вторым пользователем (или повторная запись при активной) отклоняется — за это отвечает транзакция `BEGIN IMMEDIATE` в `create_booking()` (`database/db.py`).

## Что осознанно НЕ входит в MVP

Оплата, онлайн-карты, уведомления/напоминания, CRM, админ-панель. Это аккуратный MVP для портфолио: только запись и её просмотр/отмена.

## Веб-витрина «Северный клинок» (`docs/`)

Статический демо-сайт вымышленного барбершопа — та же предметная область,
что и у бота, но для браузера. Все названия, цены, мастера, отзывы и адрес
**придуманы**; на каждой странице явно сказано, что это демо, а не действующий
бизнес. Своя визуальная система: бумага + графит + латунь, serif-заголовки,
без фреймворков и сборки — чистые HTML/CSS/JS.

**Сценарий записи:** услуга → мастер (или «кто свободен раньше») → дата
и время → имя/телефон → проверка → подтверждение с кодом вида `СК-XXXXXX`.
Назад — на любом шаге, выбор правится без потери остального. Занятое время
выбрать нельзя; занятость считается тем же детерминированным правилом, что
и `seed.py` бота (`(mi + di + ti) % 3 == 0`), плюс ваши демо-записи.
Раздел «Мои демо-записи» показывает записи и позволяет отменить (окно
освобождается). Валидация: имя от 2 букв, телефон +7/8 + 10 цифр, обязательный
чекбокс понимания демо-режима.

**Честный демо-режим:** сервера нет, ничего никуда не отправляется.
Записи хранятся только в `localStorage` вашего браузера.

**Открыть локально:**

```powershell
cd barberflow
py -m http.server 8092 --directory docs
# http://127.0.0.1:8092/
```

**GitHub Pages:** сайт публикуется из папки `docs/` без сборки
(Settings → Pages → Deploy from branch → `main` → `/docs`).
Telegram-бот на Pages работать не может (нужен Python-процесс с polling),
поэтому публикуется только витрина — это задокументировано и здесь, и на сайте.

**Проверено локально (headless Edge, 2026-10-10):**
ширины 320/375/390/430/768/1440/1920 — ноль JS-ошибок, ноль горизонтального
переполнения; сквозной сценарий (пустая отправка блокируется, выбор услуги →
«кто свободен» → дата → время → невалидный телефон блокируется → корректный →
подтверждение → код + запись в localStorage → отмена освобождает окно);
`tests/test_db_tmp.py` — seed идемпотентен, двойное бронирование и чужой
`master_id` отклоняются, отмена возвращает слот.
